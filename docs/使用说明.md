# 随心写作 · 使用说明

> 写作与改稿的桌面应用。选中一段、一句或一节，让 AI 润色、精简、扩写或续写；
> 所有修改先以对照形式呈现，由你逐处确认后才写入，并记入这一段的版本历史。

设计原则：**作者主权**（AI 从不直接改动正文）、**手感优先**、**本地优先**（文稿自动保存在本机，Key 存系统安全区）、**状态可移植**（工程文件自描述，外部 agent 可接力）。

技术栈：Tauri 2（Rust 壳）+ React 18 + TypeScript + Vite + Zustand + Immer + diff-match-patch。
产品规格见 [spec.md](../spec.md)，前端设计见 [design.md](../design.md)，本轮改进的来龙去脉见 [docs/改进计划.md](改进计划.md)。

## 快速开始

### 浏览器模式（无需 Rust，先跑起来）

```bash
npm install
npm run dev        # http://localhost:5173
```

浏览器模式下能力自动降级：文稿库存 IndexedDB、打开文件用 `<input type=file>`、另存为 / 导出走浏览器下载、API Key 存 `localStorage`（仅开发用）。

### 桌面模式（Tauri 2）

需要 [Rust 工具链](https://www.rust-lang.org/tools/install)（stable ≥ 1.77）。

```bash
npm install
npm run tauri dev      # 开发：壳 + 前端热更新
npm run tauri build    # 打包安装包（nsis / msi）
```

桌面模式下：文件对话框走原生；文稿库在应用数据目录（`library/`）；绑定了文件的文稿会同时写回该文件；API Key 写入系统安全区（Windows Credential Manager / macOS Keychain / Linux Secret Service，见 `src-tauri/src/main.rs`）；AI 请求由 Rust 侧发出（`tauri-plugin-http`），不受跨域限制，本机模型（如 Ollama）和不返回跨域头的网关也能直接用。

Windows 上还需要 Visual Studio 的"使用 C++ 的桌面开发"组件（MSVC 与 Windows SDK）和 WebView2（Windows 10/11 自带）。

应用图标由 `src-tauri/icons/icon.svg` 生成：改完源图后运行 `npx tauri icon src-tauri/icons/icon.svg`，只保留 `tauri.conf.json` 用到的几个文件即可。

### 测试

```bash
npm run typecheck
npm test           # 单元测试（Vitest）：Markdown 往返、文档操作、工程迁移、diff、agent 协议、命令行与 MCP
npm run e2e        # 端到端测试（Playwright，AI 接口在测试内模拟）
```

首次在本机运行 e2e 前需要 `npx playwright install chromium`。

| --- | --- |

| AI | 空格唤起指令框，作用于当前选区：一段 / 连续多段 / 段内一段文字 / 一节；快捷指令 润色 · 精简 · 扩写 · 更口语 · 更正式 · 续写；写作设定随每次请求发送 |
| 对照确认 | 标注 / 修改后 / 对照三种看法；改动小逐处裁决，改动大整体决定；接受 · 改一改 · 再来一版（多候选）· 放弃 · 稍后；原文变了自动标记过期 |

| 设置 | AI 服务为应用级设置，内置 DeepSeek / 通义千问 / Kimi / 智谱 / OpenAI / 自定义；风格 稳妥 / 平衡 / 发散；正文字体 宋体（内置）/ 黑体 / 楷体；正文字号（默认随窗口变大，1440 宽时 17px、2K 全屏约 22px，也可固定）；正文宽度 适中（每行约 40 字）/ 宽（约 52 字）/ 铺满；深浅主题 |

## 快捷键

按 `?` 查看应用内完整列表。

- **选择**：点击 / `↑` `↓` 选中；`Shift+点击` / `Shift+↑↓` 连续选中多段；鼠标划选段内文字
- **写作**：`E` / `Enter` / 双击 编辑；`Esc` 或点击别处完成
- **Markdown**（编辑时选中文字）：`Ctrl+B` 加粗 · `Ctrl+I` 斜体 · `Ctrl+Shift+X` 删除线 · `Ctrl+E` 行内代码 · `Ctrl+K` 链接；再按一次取消
- **AI**：`空格` 或 `/` 唤起；不写要求直接回车 = 润色；生成中 `Esc` 中断
- **对照确认**：`Enter` 接受 · `E` 改一改 · `R` 再来一版 · `←` `→` 切换候选 · `Backspace` 放弃 · `Esc` 稍后 · `V` 切换看法 · `Tab` 换一处 · `Y` / `N` 接受 / 拒绝这处
- **缩放**（桌面版）：`Ctrl+=` 放大 · `Ctrl+-` 缩小 · `Ctrl+0` 还原，整个界面一起缩放
- **文件**：`Ctrl+N` 新建 · `Ctrl+O` 打开 · `Ctrl+S` 保存 · `Ctrl+Shift+S` 另存为 · `Ctrl+Shift+E` 导出 Markdown · `Ctrl+Z` / `Ctrl+Y` 撤销 / 重做

## 让 agent 操作文稿（`suixin` 命令行）

Codex、Claude Code、Kimi Code 等任何能跑 shell 的 agent 都可以用 `suixin` 无头地读写工程文件：

```bash
npm run build:cli && npm link        # 得到全局命令 suixin（或 node dist-cli/suixin.mjs）
suixin guide                         # 写给 agent 的完整用法
suixin outline 稿.suixin.json
suixin replace 稿.suixin.json --quote "原文里的一句" --text "改后的一句" --why "理由" --as "Codex"
echo '[{"op":"note","target":{"section":"引言"},"issue":"太短","advice":"补一句"}]' | suixin apply 稿.suixin.json -
```

- **默认只提建议**：agent 的修改成为署名的待确认建议（带理由，一次调用为一组），作者在 App 的「待办」里逐条或整组接受 / 放弃，正文不会被直接改动。
- **直接修改需要作者授权**：在 App 的「AI → Agent 访问」里为这篇文稿选「允许直接修改」（需二次确认，可随时收回），agent 调用时还须显式加 `--direct`。改标题、移动章节等结构操作只在此模式下可用。直接修改同样署名、记入版本历史、可撤销。
- **定位不靠行号**：用逐字引文 `--quote`（不唯一时报 `AMBIGUOUS` 并给出候选）、段落 id 或章节标题；批量操作要么全部成功要么全不生效；`--dry-run` 只看结果；输出一律 JSON，失败时带 `hint`。
- **与 App 同时使用**：桌面版会每 2 秒检查绑定的工程文件，保存前也会先比对。外部只加了建议时直接合并；改了正文而这边没有未保存改动时自动载入（Ctrl+Z 可退回）；两边都有改动时暂停保存，由作者选择保留哪一份。外部对授权字段的改动一律忽略并立即写回。
- **MCP 服务**：`suixin mcp` 以 stdio MCP 服务暴露全部操作（外加 `apply`、`new_document`、`export_markdown`、`guide` 与下面的实时协作工具），署名按客户端自动识别（Claude Code / Codex / Kimi Code…），也可 `--as` 指定；`--file` 可设默认文稿。
  - Claude Code：`claude mcp add suixin -- suixin mcp`
  - Codex：`codex mcp add suixin -- suixin mcp`
  - 其他 harness（如 Kimi Code）：通用配置 `{"mcpServers": {"suixin": {"command": "suixin", "args": ["mcp"]}}}`
- **Skill 模板**：`integrations/skills/suixin/SKILL.md` 可放进 Claude Code 的 `.claude/skills/` 或 Codex 的技能目录；其他 harness 在 `AGENTS.md` 里写一句"操作 .suixin.json 前先运行 `suixin guide`"即可。

### AI 味自检

```bash
suixin flavor 稿.suixin.json                          # AI 味指数、每处命中（quote 可直接定位）与改法
suixin flavor 稿.suixin.json --text "改后的句子"        # 提建议前自检
suixin baseline build 我 我的旧作.txt --default         # 用作者自己的文字建立个人基线（与 App 共用）
```

agent 的 `replace` / `insert` 如果带进了新套路（或只是换了说法，比如把"不是…而是…"改成"不是…，是…"），返回里会附 `flavor` 提醒。MCP 工具同名 `flavor`。

### 图片、排版预览与导出

文稿里的图片是单独一段 `![图注](稿.assets/xxx.png)`：图片放在工程文件旁边的 `稿.assets/`（按内容命名，同一张图只存一份），导出的 Markdown 是标准写法。App 里可以粘贴、拖入或右键插入图片，按 E 改图注。

```bash
suixin images 稿.suixin.json                              # 所有图片：图注、本机路径、尺寸
suixin image add 稿.suixin.json 图.png --after-section "引言" --caption "图注"   # 默认成为待确认建议
suixin image show 稿.suixin.json --block <图片段落id>       # 给出图片文件路径，多模态模型直接看
suixin render 稿.suixin.json --style zhihu -o 预览/          # 按页截图，检查版面
suixin export 稿.suixin.json --format html|md|pdf -o 输出    # html 单文件（图片内嵌）；md 连同 .assets/
```

MCP 对应 `images`、`insert_image`、`view_image`（直接返回图像）、`render_preview`（直接返回截图）、`export_document`。

**发到知乎**：`suixin export 稿.suixin.json --format zhihu -o 发布包`（MCP `zhihu_package`）生成 `publish.js`。在已登录的知乎「写文章」页执行它，标题、正文与图片会按顺序填进草稿，图片由知乎自己上传（做法是在编辑器上合成粘贴事件）。脚本**不会点"发布"**。不能执行脚本时，在 App 里用「文件 → 发布到知乎…」逐段复制粘贴。PDF 与截图借用本机的 Chrome 或 Edge（DevTools 协议，无需另装浏览器；`SUIXIN_BROWSER` 可指定）。

### 与开着的 App 实时协作（桌面版）

桌面版启动后在本机开一条实时通道：只监听 `127.0.0.1` 的随机端口，端口与随机令牌写在应用数据目录的 `bridge.json`（Windows 为 `%APPDATA%\com.aiwriter.app\`），每个请求都要带令牌，并校验 Host；App 退出时删除该文件。命令行与 MCP 会自动找到它：

```bash
suixin status                                   # App 是否在线、打开的是哪篇、作者选中了什么
suixin replace @ --quote "…" --text "…"         # @ = 作者正在看的那篇；建议立即出现在作者眼前
suixin selection                                # 作者的选区，附现成的定位
suixin wait --since 0                           # 等作者接受 / 放弃建议、交办任务、改选区…
suixin tasks @ ; suixin claim @ <id> ; suixin done @ <id> --summary "…"
suixin request-access --why "要调整章节顺序"     # App 里弹窗，作者点允许才生效
```

- App 开着且打开的正是这个文件时，操作在 App 里的文稿上执行（读到的是含未保存改动的最新内容），照常自动保存；否则退回直接读写文件。App 回复的错误（如未授权）不会退回文件，不能借此绕过作者。
- 在线时权限以 App 为准，不看文件里的字段；直接修改不会动作者正在编辑的那一段，并给作者一个"撤销"。
- **交给 Agent**：作者在 AI 指令框写下要求后点「交给 Agent」，任务连同选区存进文稿（App 没开时 agent 也能从文件里看到），进度显示在「待办」里。
- MCP 里对应的工具：`app_status`、`get_selection`、`wait_for_events`、`request_direct_access`、`tasks`、`claim_task`、`complete_task`；各操作的 `file` 参数可省略。
- 环境变量 `SUIXIN_NO_BRIDGE=1` 可强制只读写文件。

> 说明：App 没开时，能写文件的程序在技术上可以改动授权字段；App 打开时会忽略并纠正对授权字段的篡改，在线时授权只以 App 为准。

## 工程文件与外部 agent 续作协议（`suixin/project@2`）

工程文件（`.suixin.json`）自描述，任何外部 agent 都可以接力处理：

```jsonc
{
  "schema": "suixin/project@2",
  "meta": { "title": "…", "createdAt": "…", "updatedAt": "…", "language": "zh" },
  "brief": "写作设定（可选）",
  "blocks": [
    { "id": "h_…", "type": "heading", "level": 2, "text": "引言", "versions": [/* … */] },
    { "id": "b_…", "type": "paragraph", "text": "当前生效的正文", "status": "pending",
      "versions": [{ "v": 0, "text": "…", "source": "import", "instruction": null, "at": "…" }] }
  ],
  "suggestions": [
    { "id": "s_…", "kind": "ai_diff", "state": "pending",
      "target": { "blockIds": ["b_…"], "range": null },
      "original": "生成时的原文", "proposed": "建议的新文本",
      "instruction": "用户的要求（可为 null）", "diff": [{ "op": "keep", "text": "…" }],
      "author": { "kind": "agent", "name": "Codex" }, "why": "理由", "changeset": "cs_…" }
  ]
}
```

1. 待办 = `suggestions[state=pending]`。`target.blockIds` 是被替换的连续段落；有 `range` 时只替换那一段落里 `[start, end)` 的文字；`blockIds` 为空时表示插在 `insertAfter` 之后。`kind: "note"` 是只给建议不给文本的检查结果。
2. 处理后把 `state` 置为 `accepted` / `rejected`，相应改写 `blocks[].text` 并在该块 `versions` 末尾追加一个版本。
3. 若 `original` 与目标位置当前的文字不一致，说明原文已被改动，这条建议应视为过期。
4. `blocks[].status` 是方便阅读的派生字段，读取时会被忽略；不认识的字段必须原样保留。
5. 旧版 `ai-writer/project@1` 文件打开时自动迁移。
6. `meta.agentAccess`（`propose` / `direct`）只能由作者在 App 里设定；agent 提的建议带 `author` / `why` / `changeset`，同一 `changeset` 可整组处理。
