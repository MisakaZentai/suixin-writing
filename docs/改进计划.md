### 与计划的出入

- **没有做列表虚拟化**：改为段落存储后块数下降一个量级，实测已达标；如以后放宽 20 万字上限再考虑。
- **没有做"悬停时句子淡高亮"**：段内片段改用鼠标划选（更通用），这一项不再需要。
- **评审里"单字母快捷键会被输入法吞掉"说得过重**：焦点不在输入框时输入法并不介入。仍统一改为按物理键位识别并跳过组字事件，作为保险。
- **撤销历史按文稿独立**：切换文稿会清空撤销栈；跨文稿的撤销没有意义，且会引出更多边界问题。

## 已拍板的方向

| 决策 | 结论 | 理由 |
|---|---|---|
| 产品定位 | 补齐写作能力，不退回"纯改稿台" | 改稿时天然会出现"这里补一段"，写和改不该分成两个工具 |
| 粒度开关 | 取消全局"句子 / 段落 / 全文"开关，改为**选了什么就改什么** | 粒度是把存储模型暴露给用户；也是回退删段、全文并段、合并无效等问题的根源 |
| 存储单位 | 段落是持久单位，标题进入正文，大纲由标题生成；句子只在显示和 AI 选区时临时切分 | 一份数据、一处历史，彻底消除大纲与正文不同步 |
| 文件格式 | `suixin/project@2`（`.suixin.json`），读取 `ai-writer/project@1` 时自动迁移 | 模型变化必须升版本；外部 agent 协议同步更新 |
| 保存方式 | 所有文稿自动保存：未指定位置的存在"文稿库"，指定位置的写回文件；Ctrl+S 立即落盘，首次可选位置 | 用户不该再因为"导入""忘了导出"而丢稿 |
| AI 服务配置 | 应用级设置 + 服务商预设；工程文件里的接口地址不再参与请求 | 修复 Key 被发往他人地址的安全问题，也符合"配置归属" |
| 品牌 | 界面、窗口、安装包、文件格式统一为「随心写作」；Tauri identifier 与 keyring 服务名等内部标识保持不变 | 改内部标识会让已保存的 Key 和应用数据目录失联 |

## 步骤

### 第 0 步 · 工程基线
- 引入 Vitest（纯逻辑与 store 单测）和 Playwright（端到端测试，`npm run e2e`）。
- 本文档入库。

### 第 1 步 · 止血（在现有模型上做最小修复）
1. 浮动操作条、右键菜单、版本历史弹层恢复可见：`content-visibility` 从块根节点移到正文层；菜单类浮层挂到 `body` 上。
2. 输入框里的 Ctrl+Z / Ctrl+Shift+Z 交还给输入框自己；Windows 习惯的 Ctrl+Y 作为重做。
3. AI 服务配置改为应用级：服务商预设（DeepSeek / 通义千问 / Kimi / 智谱 / OpenAI / 自定义），每家独立的 Key，改动即时保存，没打开文稿也能配置；温度改为"稳妥 / 平衡 / 发散"。
- 验收（e2e）：只用鼠标完成"选中 → 操作条 → AI → 确认"；编辑中按 Ctrl+Z 文稿不丢；打开写有陌生接口地址的工程文件，请求仍只发往本机配置的地址。

### 第 2 步 · 数据模型 v2（地基）
- 新类型：`HeadingBlock { id, type:'heading', level, text, versions }`、`ParagraphBlock { id, type:'paragraph', text, versions }`；建议（Suggestion）以"目标段落 id 列表 + 可选段内字符区间 + 生成时原文"定位。
- 纯函数文档操作库：编辑、拆分、合并、插入、标题 ↔ 正文转换、回退、章节范围、章节移动与升降级、建议的增删改与应用。
- 导入 / 导出重写：规范化的 Markdown 导入后原样导出逐字节一致；保留段内换行；v1 工程自动迁移。
- projectStore 改用新操作库；界面适配：正文渲染标题、去掉粒度开关、大纲由标题生成、版本历史按段落。
- 验收：评审中 P0-3 / 4 / 5 全部消失（单测 + e2e）；5 万字文档点选响应显著下降（目标 < 100ms）。

### 第 3 步 · 写作能力
- 新建空白文稿。
- 编辑语义：回车分段、Shift+回车段内换行、段首退格与上一段合并、在首行 / 末行按 ↑ / ↓ 跨段移动、Esc 或点击别处即完成（不再"取消即丢"）、双击进入编辑且光标落在点击处。
- 以 `#` 开头的段落自动转为标题；右键"在下方插入段落""转为标题 / 正文"。

### 第 4 步 · 文件与保存
- 文稿库：浏览器用 IndexedDB，桌面版用应用数据目录；绑定文件的文稿直接写回文件。
- 自动保存（停笔约 1 秒后）+ 顶栏保存状态（"已保存" / "正在保存…" / 出错可重试）；关闭窗口前强制落盘。
- 快捷键：Ctrl+N 新建、Ctrl+O 打开、Ctrl+S 保存、Ctrl+Shift+S 另存为、Ctrl+Shift+E 导出 Markdown。
- 启动页：新建空白 / 打开文件 / 粘贴导入 / 最近文稿 / 示例。导入永远新建文稿，不替换当前文稿；整个窗口都接受文件拖放。
- 顶栏重组为「文件」菜单，"打开"不再藏在"导出"里。

### 第 5 步 · AI 交互
- 作用范围由选区决定：点击 = 一段；Shift+↑ / ↓ 或跨段划选 = 连续多段；段内划选 = 一个片段；大纲节点 = 一节。跨章节选区给出明确提示。
- 统一的 AI 指令框（空格唤起）：留空回车 = 润色；快捷指令（精简 / 扩写 / 更口语 / 更正式 / 续写）；最近用过的指令。
- 文稿级"写作设定"（读者、语气、禁用词等）随每次请求发送。
- 出错就地显示在块上，可重试、可看详情；没配 Key 时入口标示，第一次使用时就地展开配置卡片。
- 快捷键统一用 `KeyboardEvent.code` 判断并跳过输入法组字事件。

### 第 6 步 · diff 重做
- 词级 diff（`Intl.Segmenter`）+ 按分句聚簇，不再按"间隔 2 个字"切碎。
- 默认"结果视图"：一段仍是一段，新增加下划线和浅底，删除以小号删除线留在原位；可切换"对照视图"。
- 按改动比例自适应：改动小逐处裁决，改动大作为整体候选。
- 操作：接受（Enter）/ 改一改（E）/ 再来一版（R，多候选 ‹ ›）/ 放弃（Backspace）/ 稍后（Esc，保留为待确认）。取消自动提交。
- 原文在建议生成后被改动时，标记"已过期"，只允许重新生成或放弃。

### 第 7 步 · 大纲即结构
- 拖拽大纲节点 = 移动整节（含子节与正文）；升级 / 降级；重命名 = 改标题。
- 节点操作：扩写本节、精简本节、检查本节（产出建议）。
- AI 反推大纲改为"插入标题"的提案，预览确认后生效；全文检查产出逐段建议。
- 「待办」只在有待处理内容时出现。

### 第 8 步 · 视觉与细节
- 品牌统一；去掉 Google Fonts 外链，内置正文字体并提供字体选择。
- 次要文字对比度达到 WCAG AA（≥ 4.5:1）；diff 新增加下划线，不只靠颜色。
- 动效收敛：去掉常驻呼吸与"全部接受"波浪延迟，动效只用于解释因果。
- 提示条只用于后台任务完成与错误；帮助面板按新快捷键重写。

### 第 9 步 · 性能与文档收尾
- 订阅与派生计算优化，必要时列表虚拟化；5 万字基准写入 e2e。
- 更新 README、spec.md、design.md 与外部 agent 续作协议（v2）。

## 风险与待验证（需要在桌面环境确认）

> 2026-09-24 已在 Windows 11 实机逐项验证，结论见下方「桌面环境验证结果」。

- **桌面版跨域**：AI 请求从 WebView 直接发出，部分服务商可能不返回 CORS 头。需在装有 Tauri 依赖的 Windows 机器上验证；不通时改用 `tauri-plugin-http` 由 Rust 侧转发。
- **中文安装包名**：`productName` 改为「随心写作」后，MSI（WiX）需要中文代码页，已设 `bundle.windows.wix.language = zh-CN`；需在 Windows 上实际打包确认，不行就把 productName 退回 ASCII、只保留中文窗口标题。
- **Rust 侧**：本轮 Rust 代码只改了注释。云端容器缺少 GTK 等桌面系统库，`cargo check` 无法完成；改过的 `tauri.conf.json` 已用 Tauri CLI 自带的 JSON Schema 校验通过。桌面打包需本机验证。
- **性能数字**：在云端无头浏览器测得，绝对值偏悲观，以相对改善为准。
- **桌面版文稿库与拖放**：文稿库的应用数据目录读写、Tauri 拖放事件只在浏览器模式下测试过同一套逻辑的浏览器分支，桌面分支需本机验证。
- **中文下载文件名**：云端无头 Chromium 会把中文下载文件名替换成 "download"，真实浏览器与桌面版不受影响；相关测试只校验内容。

# 第二轮：让 agent 原生地操作随心写作

> 目标：Codex、Claude Code、Kimi Code 等任何 harness 都能舒适地读写文稿（无头命令行 / MCP），
> 并能在作者使用 App 时实时协助调整文字与图片排版。

## 已拍板

| 决策 | 结论 |
|---|---|
| agent 的写权限 | 默认**只能提建议**（落为待确认修改，由作者在对照里拍板）；**直接修改**需作者在 App 里为这篇文稿明确授权，可随时收回；直接修改同样记入版本历史、可撤销、署名 |
| 编辑器 | 暂不换富文本编辑器；行内格式沿用 Markdown 语法，阅读态渲染 |

## 架构

一套操作协议（每个操作有 JSON Schema），三个入口：

- **`suixin` 命令行**：无头，直接读写工程文件；任何能跑 shell 的 harness 都能用；
- **`suixin mcp`**：stdio MCP 服务，操作即工具；
- **实时桥**：App 在线时，命令行 / MCP 通过本机 hub 把操作交给 App 执行，改动直接出现在作者眼前的对照里。

协议要点：按引文 / 段落 id / 章节定位；写操作默认产出建议并带署名、理由、变更集；携带原文做冲突检测；
批量操作要么全成功要么全不生效；`--dry-run` 只看结果不写入；输出一律 JSON。

## 阶段

| 阶段 | 内容 | 验收 |
|---|---|---|
| A1 | 无头核心 + 操作协议 + `suixin` 命令行；App：Agent 访问授权、建议署名与变更集（整组接受 / 放弃）、绑定文件被外部修改时自动载入或提示冲突（不再被自动保存覆盖）；`suixin guide` 与 skill 模板 | agent 用命令行给文稿提建议，App 打开后能看到署名并逐条 / 整组确认；未授权时结构性修改被拒绝 |
| A2 | `suixin mcp` | 三种 harness 各一行配置即可调用全部操作 |
| A3 | 实时桥：在场提示、选区读取、事件流、"交给 Agent"任务、在线授权弹窗 | App 开着时 agent 的建议实时出现；作者的接受 / 拒绝实时回传 |
| A4 | 图片块、文件夹工程格式、文档主题与具名段落样式、渲染与导出（HTML / PDF / PNG 截图） | agent 能插图、调样式，并通过截图检查版面 |

## A2 执行结果（2026-09-24）

- `cli/mcp.ts`：无依赖的 stdio MCP 服务（JSON-RPC 2.0，一行一条消息；协议版本 2025-06-18 / 2025-03-26 / 2024-11-05），与命令行共用 `cli/files.ts`（原子写入、写前比对重试）与同一套操作、权限。
- 工具：18 个文稿操作 + `apply`、`new_document`、`export_markdown`、`guide`；写操作带 `direct` / `dry_run`；工具注解标明只读 / 破坏性；操作失败以 `isError` 结果返回（带 hint 与候选），不当作协议错误。
- 署名按客户端名自动识别，`--as` 可覆盖；`--file` 设默认文稿后各工具的 file 参数可省略。

## A3 执行结果（2026-09-24）

- **本机通道（`src-tauri/src/bridge.rs`）**：App 启动时在 `127.0.0.1` 的随机端口开 HTTP 服务（`tiny_http`），端口与随机令牌（192 位）写进应用数据目录的 `bridge.json`，退出时删除。每个请求校验令牌与 Host（防 DNS 重绑定）。Rust 只做三件事：把请求转给前端执行并等回复、`events.wait` 长轮询（事件环形缓冲 500 条）、维护在线的 agent。
- **App 端（`src/bridge/`）**：请求在 App 里的文稿上执行，复用同一套 `runOps`，结果进撤销历史、照常自动保存。在线时权限只以 App 为准；直接修改不动作者正在编辑的段落，并给作者"撤销"；处理外部修改冲突期间不接受操作。作者的动作以事件发出：`suggestion.resolved`、`task.created` / `task.cancelled`、`access.changed`、`document.opened` / `closed`、`selection.changed`（400ms 防抖）。
- **命令行 / MCP**：自动发现 App；App 开着且打开的正是这个文件（或写 `@`）时交给 App，否则退回读写文件；App 回复的错误不会退回文件。新增 `status`、`selection`、`wait`、`request-access`、`tasks` / `claim` / `done`；MCP 新增 `app_status`、`get_selection`、`wait_for_events`、`request_direct_access`，各操作的 `file` 可省略。
- **界面**：顶栏显示在线的 agent；AI 指令框里「交给 Agent」；待办里的任务卡片（等待接手 / 处理中 / 已完成 + 说明）；授权弹窗（默认焦点在"拒绝"，Esc 即拒绝）；「Agent 访问」面板显示实时连接与在线 agent。
- **任务存在文稿里**（`tasks` 字段，旧文件兼容），App 没开时 agent 也能从文件看到；经文件的接手 / 完成会并入 App（作者取消的以作者为准）。
- **顺带修复**：读操作的结果引用了 immer 草稿，执行完就失效——`suixin suggestions` 在有建议时直接报错（A1 起就有），现在结果在草稿有效时转成普通 JSON。
- **测试**：单元 107 项（新增 App 端处理、命令行路由 / 退回 / 离线、任务、同步）；端到端 66 项（新增 4 项：建议实时出现并回传接受、交给 Agent 全流程、在线授权、读取选区——本机服务用与 Rust 同约定的测试替身）；桌面实机 18 项（真实 App + 真实命令行 / MCP 进程：令牌与 Host 校验、实时建议、事件、选区、授权弹窗、结构修改、MCP 署名、退出清理、离线提示）。

与计划的出入：
- 没做"在场提示"的反方向（告诉作者 agent 正在看哪一段）：目前只显示谁在线、谁在等待；等有具体场景再加。
- App 没开时授权字段仍可能被改：要彻底解决，需要把授权移出工程文件，由 App 保存、命令行离线时无从得知——这会让"App 没开也能授权直接修改"不可用。先保持现状，由 App 打开时纠正。

## A4 调整（2026-09-24）：围绕"发布"

目标改为：agent 能把文稿按原格式发到知乎等平台（图片必须跟着走），多模态模型能方便地看图、看排版效果。

已拍板：
- **图片存在文稿旁边的资源文件夹**：`稿.suixin.json` 旁边放 `稿.assets/`（与 Typora 相同），文稿里用相对路径引用；文稿库里的文稿对应 `library/<id>.assets/`。另存为时连图片一起复制。
- **文档主题与具名段落样式先不做**：各平台用自己的样式，对发布没有帮助。

知乎的做法（调研结论）：知乎编辑器自带的"导入文档"对 Markdown / Word 支持不稳定，图片常常上传失败；
可靠的做法是在编辑器页面里合成粘贴事件，按顺序放入 HTML 片段与图片文件，由知乎自己的上传流程把图片传到知乎图床
（标题、列表、引用、代码块、加粗、链接可保留；表格、分割线会退化）。这需要 agent 能在浏览器页面里执行脚本；
纯 computer use 只作兜底。脚本只负责填进草稿，**从不点"发布"**，由作者确认后自己发。

| 步骤 | 内容 |
|---|---|
| A4.1 图片块 | 新块类型 image（图片 + 图注）；Markdown 里单独一行的 `![图注](路径)` 即图片块；App 里粘贴 / 拖入 / 菜单插入图片，改图注，图片缺失时占位提示；资源文件夹的读写与另存为复制 |
| A4.2 agent 看图与插图 | `read` 输出图片块（图注、绝对路径、尺寸）；`suixin image add` / MCP `insert_image`（默认成为待确认建议）；MCP `view_image` 直接把图片交给多模态模型 |
| A4.3 渲染与导出 | 同一套渲染：自包含 HTML、Markdown + 图片文件夹；命令行借本机 Edge / Chrome 无头模式出 PDF 与分页 PNG；MCP `render_preview` 把排版截图交给模型检查 |
| A4.4 知乎发布包 | `suixin export --format zhihu`：知乎兼容的 HTML、图片、一段自包含的填稿脚本与说明；App「导出 → 知乎发布包」；在作者同意后用真实账号的草稿验证 |

## A4 执行结果（2026-09-24）

| 步骤 | 结果 |
|---|---|
| A4.1 图片 | 图片就是内容只有一行 `![图注](稿.assets/xxx.png)` 的段落（梳理发现新增块类型要改四五十处、其中读取时会丢图，故不新增类型）；资源放在工程文件旁边的 `.assets/`，按内容命名；粘贴 / 拖入 / 右键插图，E 改图注，换图；另存为复制图片，从 Markdown 文件导入收进本地图片；图片不合并、不拆、不转标题、不计字数，内置 AI 不改写图片、整节改写时保住图片行 |
| A4.2 agent 看图与插图 | read / images 报出图片的本机路径与尺寸；`image add` / insert_image 存图后以建议插入；`image show` / view_image（直接返回图像）；插入位置下方提示"Codex 想在下面插入图片"，对照里显示成图 |
| A4.3 渲染与导出 | 同一套渲染（marked）：HTML 单文件、Markdown 连同 .assets/、PDF、分页截图；render_preview 直接返回截图。浏览器经 DevTools 协议控制；Windows 版 Edge 不输出 --dump-dom、有更新待装时会转交进程，改用端口 + DevToolsActivePort（附最小 WebSocket 客户端） |

顺带修复：已绑定文件的文稿另存为新文件时可能误报外部冲突；读操作结果引用 immer 草稿导致 `suixin suggestions` 在有建议时报错；从文稿库删除文稿时图片文件夹残留。
