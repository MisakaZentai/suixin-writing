# AI 味：检查、评分与消除

> 来源：作者自己的实践（`D:\Penguin Hraness`：AI查找 检测器、round_score 基线评分、瑶光病灶库与"开庭"流程、去 AI 味技能与实验记录），
> 加上开源项目：lieflat-less-ai-tone（283 万字对照语料实测）、DW-Studio/sloplint、mochi-ruler、Humanizer-zh / humanizer-chinese、
> blader/humanizer、sam-paech slop-score / slop-forensics、oh-story story-deslop、Wikipedia「Signs of AI writing」。
> swaylq/humanize-chinese 是非商用许可，只借思路不借代码与词表。

## 一、原则（取舍的依据）

1. **定位大于判断。** 数字只用来找嫌疑，由作者定案（"数字找嫌疑，人定案"）。给的是"AI 味指数"（相对作者基线的超标程度），不是"AI 写的概率"。每一处命中都能说清：哪条规则、为什么、往哪改。
2. **按作者基线算超标。** 作者自己也常用的词有豁免额度（作者密度 × 1.5 以内不计），作者从来不用的句式一出现就重罚。这条沿用 round_score。没有个人基线时，用内置的中文人类基线（lieflat 的人类语料实测值）。
3. **句式没有罪，用法才有罪；控密度，不清零。** "不是握，是抓"是好句子，所以"不是 X 而是 Y"每三千字允许一两处。"微微、轻轻"是正常中文，过密才提醒，并且只记录不强改（这是 W-001 的教训：删掉会伤画面）。
4. **对白和旁白分开看。** 对白里的"不是 X，是 Y"、语气词、省略号多半是人物口吻，叙述专用的规则跳过引号内的文字。
5. **词表会过时，统计要谨慎。** 只收经过验证的特征。实测区分度低的，只作低权重提醒，或者干脆不收：单个网文套语词的 AUC 只有 0.38–0.60，反问句人类和 AI 差不多；比喻和排比人类用得反而更多。句长均匀度与文体有关，只在整章层面低权重使用。
6. **LLM 只做两件事：改写，和（可选的）找漏网。** 不拿 LLM 复核正则命中：它和正则同一个视角，纠不了错，反而把合理的修辞判成 AI 味（AI查找 v0.5 的结论）。
7. **删是最差的处理，好的去味是替换。** 改写要功能守恒：信息不增不减，情绪落点句只换说法不删，人物标志性意象保留，不能用一种套路替换另一种。
8. **正例胜过禁令。** 光靠提示词禁令压不住模型的深层指纹（"不是 X 而是 Y"是典型）。所以改写时附上作者自己的低 AI 味段落当示范，并且在程序里复检，不能只靠提示词。示范段落本身也要先过检，避免拿到"有毒的基准"。

## 二、检查什么（规则库）

每条规则记录：编号、名称、类别、严重度（high / medium / low / reminder，对应权重 10 / 4 / 2 / 1）、适用文体（小说 / 文章 / 通用）、
范围（全部 / 仅旁白）、匹配方式（正则 / 词表 / 统计）、内置人类基线（每万字）、说明、改法、证据来源。

| 类别 | 规则（示例） | 严重度 | 证据 |
|---|---|---|---|
| 句式 | 否定-修正：不是 A，(而/只)是 B；不是…。是…；不是…——是…（旁白） | high | lieflat 3.4×；AI查找；病灶库 S-001 |
| 句式 | 升华递进：不仅仅是…更是 / 与其说…不如说 / 不只是…更是 | high | AI查找 |
| 句式 | 三连否定：不是 A，也不是 B，(只/而)是 C；没有犹豫，没有… | high | character-sim；oh-story |
| 句式 | 升华收尾：这，就是… / 或许这就是…的意义 / 段末拔高到"永远、一切、整个世界" | medium | 病灶库 C-001；Humanizer-zh |
| 句式 | 三个以上连续短句（≤8 字）同一个字开头 | medium | AI查找 parallel_structure |
| 句式 | 对称强迫：既…又… / 一方面…另一方面（密度提醒） | low | AI查找 |
| 句式 | 依然…依然…但 | medium | AI查找 |
| 句式 | 原来…也…一样 | reminder | AI查找 |
| 套话 | 论文腔过渡：综上所述、值得注意的是、毋庸置疑、不难发现… | high（小说）/ medium（文章） | AI查找；lieflat 4.4× |
| 套话 | 宣布列表的冒号、提示词冒号：以下几点：/ 核心是：/ 一句话总结：/ 说白了： | medium | lieflat 3.8–9.4× |
| 套话 | 宏大开头：随着…的(飞速)发展 / 在…的时代 | medium | Humanizer-zh |
| 套话 | 程式结尾与聊天残留：让我们拭目以待、未来可期、希望对你有帮助 | high | Wikipedia；humanizer |
| 词汇 | 黑话：赋能、抓手、闭环、底层逻辑、破局、颗粒度… | medium（文章） | ren644 等 |
| 词汇 | 拔高：彰显、注入新的活力、开启新篇章、标志着…新时代 | medium | Wikipedia |
| 词汇 | 高频虚词：仿佛、微微、轻轻、缓缓、淡淡、静静、悄然…（超过每万字 8 次才提醒，只记录） | reminder | AI查找；病灶库 W-001 |
| 叙述 | 情绪标注：感到一阵…、涌上心头、心头一紧 | medium（仅旁白） | AI查找 |
| 叙述 | 抽象感受名词：疏离感、违和感、无力感… | medium（仅旁白） | AI查找 |
| 叙述 | 空泛抒情：时间仿佛静止、空气中弥漫着、那一刻… | medium | AI查找 |
| 叙述 | 眼睛亮起 / 闪过、笑容如花、气氛模板、感官套语 | low / reminder | AI查找；病灶库 |
| 叙述 | 拟人化角色比喻：像一位…的导师 / 母亲 | medium | lieflat 7.3× |
| 叙述 | 读秒：半秒、两秒、过了一会儿；替人物解释动作的含义 | low | character-sim |
| 标点 | 破折号——：超过人类基线（约 0.8 / 千字）才计 | medium | lieflat 3.0×；各模型差 40 倍 |
| 标点 | 顿号密集列举（一句 3 项以上） | low | lieflat 1.8× |
| 结构 | 句模复用：句子指纹（开头词 + 长度档 + 骨架对 + 标点）相同的句子在全文出现 3 次以上 | medium | AI查找 structure_analyzer |
| 结构 | 句长过于均匀（CV < 0.4，至少 10 句）；段长过于均匀；转折词过密 | low（整章才算） | AI查找 statistics |
| 结构 | 一句一段的分镜式排版连续出现 | low | character-sim |

文体配置：**小说**（旁白规则全开，论文腔判重）、**文章**（知乎 / 公众号 / 议论文：黑话、宣布式冒号、宏大开头判重，叙述类规则关闭）、**通用**。
默认按引号内文字的占比自动判断，也可以手动选。

## 三、怎么算分

对每条规则 r，在适用文字（旁白规则只算引号外的文字）上：

```
密度_r   = 命中数 / max(字数, 平滑字数) × 10000        # 每万字
允许量_r = 作者基线密度_r（没有就用内置人类基线） × 1.5
超标_r   = max(0, 密度_r − 允许量_r)
罚分_r   = 超标_r × 权重(严重度) × 2                     # 与 round_score 一致
AI 味指数 = round(100 × (1 − e^(−Σ罚分 / 60)))           # 0–100，越高越重；不再截断到 0，重的之间也能排序
```

- 平滑字数：整篇或整节为 1000，单段为 600。免得一段 80 字里出现一处就直接爆表；太短的文字只标命中，不给指数。
- 同一条规则的罚分设上限（边际递减），免得一个口头禅重复 20 次就压倒其他规则。
- 分级：< 15 清爽 · 15–35 轻微 · 35–60 明显 · ≥ 60 浓重（对应 AI查找评分量表的 9–10 / 6–8 / 3–5 / 0–2）。
- 同时给出：各规则的命中数与"作者基线 vs 本文"的对照、最该先改的段落排序。
- **个人基线**：在 App 里选几篇自己写的文稿，点"用这些建立我的基线"，把各规则的计数存进应用数据目录的 `flavor-baseline.json`，命令行和 MCP 也读这一份。可以建多份（比如按笔名分），每篇文稿选用其中一份。

## 四、怎么消除

1. **定向改写，不整段重写。** 请求里带上这一段、它的命中列表（位置、规则、改法），以及作者示范段落。模式有三种：只换词、改命中所在的句子（默认）、允许调整整段结构。
2. **提示词铁律**，综合"铁律 v3"、de-ai-rewrite 技能、lieflat 和 humanizer 的规则：
   - 功能守恒，信息不增不减；不新增事实、数字、人名、引文；不改变肯定与否定的强弱。
   - 优先替换，不要删除；情绪落点句只换说法；保留对白口吻与人物口癖。
   - 不用一种套路替换另一种（不许新增破折号、三连、"不是…而是"、金句收尾）。
   - 把抽象换成具体的动作、细节或感官；可以打乱句子长短，但不许为了降分故意加噪声。
   - 篇幅变化控制在 ±30% 以内。
3. **程序复检，最多重试一次。** 用本地规则检查改写结果：出现原文没有的命中、目标命中没消掉、篇幅超出范围、数字或引号里的内容变了，就判为不合格。重试时只反馈剩下的问题。仍不合格就给出最好的一版并附上警告，不无限循环。
4. **仍由作者拍板。** 结果进入 App 原有的对照确认；确认条上显示"AI 味 42 → 8"，新增的命中用红字列出。每处命中都可以"忽略"或"这是我的风格"：前者记在文稿里，后者加进个人白名单。
5. **预防。** 内置 AI 的每次润色、改写、续写都在提示词里附上高精度禁用项；生成后自动复检，AI 自己带进来的 AI 味直接显示在确认条上。
   agent 提交的修改也一样：`replace` / `insert` 的返回里带 `flavor` 字段，改写引入了新的命中会直接告诉 agent。

## 五、放在哪里

- **App**：AI 菜单里的「检查 AI 味」打开右侧的 AI 味面板，内容有指数与分级、按规则汇总（对照基线）、最该改的段落。
  正文里的命中用波浪下划线标出，颜色按严重度，悬停看说明和改法，点一下定位。
  段落菜单和面板里都有「去 AI 味」；指令框的快捷指令里加「去 AI 味」。
- **agent**：新增操作 `flavor`（只读），可检查整篇、某一节、某一段，或检查一段尚未提交的文字；
  命令行是 `suixin flavor <文件|@> [--section 标题 | --block id | --text 文字] [--genre fiction|essay]`，MCP 工具是 `check_ai_flavor`。
  写给 agent 的使用说明里加上：提建议前先自检。
- **规则库**是一份数据文件（`src/lib/flavor/rules.ts`），带证据字段，方便以后用"挖新模式"的流程（slop-forensics 那种对照语料统计）持续补充。
